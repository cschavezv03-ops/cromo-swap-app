## Compact Rules (inject into sub-agents by context)

### Frontend (any `.tsx`/component/screen/styling work)
- Invoke `ui-ux-pro-max` skill BEFORE writing any UI code. Every screen, no exceptions.
- Recreate the Claude Design `Cromos.html` bundle pixel-perfectly (palette/fonts/screens in `CLAUDE.md` §6) — match visual output, not the prototype's structure.
- TypeScript strict. React 19 (no manual memoization). NativeWind for styling, mirror the design tokens.
- Client-side validation/filtering is UX only — never a security boundary.

### Backend / Supabase (schema, migrations, Edge Functions, RLS)
- Apply `supabase` + `supabase-postgres-best-practices` skills.
- RLS enabled on EVERY table, deny-by-default; add policies in the same change as the table.
- Service-role key is server-only (Edge Functions); never the client.
- All schema changes via migrations (Supabase MCP `apply_migration` / `supabase` CLI). Run `get_advisors` after.
- Security boundaries (scope, blocks, reservation/locking, WhatsApp-number reveal, auction penalty, university-from-email-domain) enforced in SQL/policies, not just app code. See `CLAUDE.md` §3–§4.
- USD only. Positive-price `check` constraints. Parameterized queries only. No PII in logs.

### General (all tasks)
- Conventional commits, no AI attribution / no Co-Authored-By.
- `bat`/`rg`/`fd`/`eza`/`sd` instead of `cat`/`grep`/`find`/`ls`/`sed`.
- Don't build after changes — rely on typecheck/test.
- Strict TDD where the stack supports it (becomes active once the Expo project is scaffolded with a test runner).
- Save significant discoveries/decisions/bugfixes to engram (`mem_save`, project `cromo-swap-app`).
